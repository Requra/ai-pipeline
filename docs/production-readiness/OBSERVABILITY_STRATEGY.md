# 📊 Production Observability Strategy

This document details the telemetry plan for tracking execution, performance, cost, and output quality across all nodes in the Requra.AI pipeline.

---

## 1. Migration to Structured Logging

In production, all standard output `print()` calls are replaced with structured JSON logs written to stdout. This ensures compatibility with log aggregators (e.g. Datadog, ELK, AWS CloudWatch).

### Standard Log Record Format

Every log entry must be structured as a flat JSON dictionary containing the following keys:

```json
{
  "timestamp": "2026-06-03T11:21:21.045Z",
  "level": "INFO",
  "job_id": "upload_987123987",
  "trace_id": "tr-abc123xyz789",
  "node_name": "extract_requirements",
  "message": "Chunk extraction completed",
  "duration_ms": 450,
  "input_size_chars": 4500,
  "output_count": 8,
  "model_provider": "google",
  "model_name": "gemini-1.5-flash",
  "prompt_tokens": 1024,
  "completion_tokens": 340,
  "estimated_cost_usd": 0.00025,
  "quality_score": 0.98,
  "warning_count": 0,
  "error_code": null,
  "status": "success"
}
```

## 2. Parameter Dictionary Reference

| Telemetry Key | Type | Description |
| :--- | :--- | :--- |
| `job_id` | `string` | Unique client request identifier (propagated from the input request). |
| `trace_id` | `string` | LangGraph transaction trace ID (automatically generated or passed via context headers). |
| `node_name` | `string` | Name of the active graph node. |
| `node_start_time`| `string` | ISO timestamp marking node entry. |
| `node_duration_ms`| `integer`| Execution duration of the node in milliseconds. |
| `input_size` | `integer`| Length of input text in characters or size of audio bytes. |
| `output_count` | `integer`| Count of items generated (requirements, stories). |
| `model_provider` | `string` | LLM vendor (e.g. `"google"`, `"groq"`, `"deepgram"`). |
| `model_name` | `string` | Model name (e.g. `"gemini-1.5-flash"`, `"whisper-large-v3"`). |
| `token_usage` | `dict` | Sub-dictionary: `{"prompt_tokens": X, "completion_tokens": Y}`. |
| `estimated_cost` | `float` | Estimated price of execution in USD. |
| `quality_score` | `float` | Calculated rating (percentage of grounded items / total stories). |
| `warning_count` | `integer`| Count of warnings generated by the node. |
| `error_code` | `string` | Standardized error tag if the node fails (e.g. `"TRANSCRIBE_GROQ_FAILURE"`). |
| `status` | `string` | Node execution status (`"success"`, `"partial"`, `"failed"`, `"skipped"`). |

## 3. Cost Estimation Formulas

API costs should be calculated in the telemetry formatter using the following pricing rates (updated regularly):

* **Google Gemini 1.5 Flash**:
  * Input: $0.075 / 1M tokens
  * Output: $0.30 / 1M tokens
* **Groq Whisper (large-v3)**:
  * Audio: $0.03 / hour ($0.0005 / minute)
* **Deepgram Nova-3**:
  * Audio: $0.0043 / minute ($0.258 / hour)

Formula implementation:
$$\text{Cost}_{\text{Gemini}} = \left(\text{Prompt Tokens} \times 0.000000075\right) + \left(\text{Completion Tokens} \times 0.00000030\right)$$

## 4. Alerts & Thresholds

Production alarms are triggered by the APM based on the following rules:

1. **High Error Rate**: Any job resulting in status `"error"` or `"needs_review"` where severe `quality_issues` are flagged.
2. **Slow Execution**: Any node execution duration exceeding 30,000ms (30 seconds), except transcription.
3. **Hallucination Risk**: Any job where grounding verification returns a `quality_score` below `0.85` (meaning more than 15% of requirements lack grounding evidence).
